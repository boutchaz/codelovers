# wearecodelovers

Agency website for [wearecodelovers](https://wearecodelovers.com) — built with **Astro 7**, Tailwind CSS v4, GSAP, and Bun. Fully static output served by nginx.

## Quick start

```bash
bun install
bun run dev       # dev server at http://localhost:4321
bun run build     # static build to dist/
bun run preview   # preview the production build
```

## Scripts

| Command | Description |
| --- | --- |
| `bun run dev` | Start the Astro dev server |
| `bun run build` | Build the static site to `dist/` |
| `bun run preview` | Serve the production build locally |
| `bun run encode-hero-video -- <video>` | Encode the hero background video (WebM, MP4, poster) |

## Deployment

```bash
docker compose up --build
```

Multi-stage Docker build: Bun builds the site, nginx serves it with clean URLs, gzip, immutable asset caching, and a reverse proxy for PostHog analytics (`/ingest` → `eu.posthog.com`).

## Site Structure

### Routes

- `/` - English homepage
- `/fr` - French homepage with translated content
- `/blog` - Blog listing page
- `/blog/[slug]` - Individual blog post pages
- `/case-studies` - Case studies listing page
- `/case-studies/[slug]` - Individual case study pages (LoginTel, AgroGina, WhatsApp Bot)
- `/rss.xml` - RSS feed for blog posts
- `/sitemap-index.xml` - Sitemap (generated by @astrojs/sitemap)
- `/robots.txt` - Robots.txt file

### Language Support

The site supports English (default) and French (`/fr`). Language toggle is available in the header. Future content can be added by creating corresponding `*Fr.astro` components and translations in `constants-fr.ts`.

## Analytics

PostHog is optional. Copy `.env.example` to `.env` and set `PUBLIC_POSTHOG_KEY` (EU project key from PostHog settings). Without a key the site works normally with analytics disabled.

## Blog

Posts are markdown files in `src/content/blog/`. Frontmatter:

```yaml
---
title: "Post title"
description: "Short description"
date: 2025-01-15
author: "CodeLovers"
tags: ["SaaS", "Engineering"]
language: "fr"            # "en" (default) or "fr"
product: "passion-fitness" # optional: case-study slug. Counted in analytics and picks the demo call to action
draft: true                # optional: keep the post out of the build until it is released
unlisted: true             # optional: keep the URL working but hide it from the index, feed and "read next"
cover: "booking"           # optional: picture on the blog cards (checklist, booking, belts or saas); none = text-only card
series: "gym-owners"       # optional: a key of `seriesInfo` in src/data/blog.ts
seriesOrder: 1             # optional: place in the series
resources:                 # optional: "Ressources" cards after the article
  - kind: "external"       # case-study, guide, download or external (external opens in a new tab)
    title: "Resource title"
    href: "https://example.com/"
    meta: "example.com"    # optional line under the title
---
```

An article page follows the Claude Design canvas: breadcrumb, a series badge and series navigation (`seriesInfo` in `src/data/blog.ts` holds each series' title and planned total), share buttons, the cover, a sticky table of contents built from the `##` headings, the resources, the product's demo call to action, and related posts. Reading time is the word count at 200 words a minute. The prose styles live under `.blog-prose` in `src/styles/global.css`. Markdown is sanitized, so raw HTML in a post is dropped: the design's card grid, process diagram and video player have no markdown equivalent yet.

On `/blog/` the first tag is the post's topic (the filter chips list each topic once), the newest post is the wide "À la une" card, and a series gets its own numbered block once two of its guides are published. Cover pictures are drawn in `src/components/blog/PostCover.astro`; add a kind there and to the `cover` enum in `src/content.config.ts` for a new picture.

The slug is the filename. Published posts appear automatically on `/blog` and in the sitemap.

### Releasing posts one at a time

A post with `draft: true` is left out of the build entirely: no page, no feed entry, no sitemap line, and its URL returns 404. `bun run dev` still shows drafts, so you can preview one before it goes out.

To release a post: remove `draft: true`, set `date` to the release day, commit, push, and redeploy the `web` service. The site is static, so nothing goes live until that deploy.
